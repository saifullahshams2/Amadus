## Description

`composer.lock` pins `symfony/routing` **v8.1.9**, covered by CVE-2026-118516: `CompiledUrlMatcher`/`UrlMatcher` interpret host and path differently when a route defines a host with placeholders, allowing path-based authorization rules (Symfony access_control / firewall patterns) to be bypassed. Fixed in v8.1.11 (also 5.4.56 / 6.4.50 / 7.4.23). Transitive dependency of the direct `laravel/framework` v13.38.0.

## Evidence

**Advisory evidence:** `CVE-2026-118516` applies to `symfony/routing` at installed version `v8.1.9`. The advisory is fixed in `8.1.11`.

**Transitive dependency:** introduced by the direct dependency `laravel/framework@v13.38.0`.

**Dependency chain:** `laravel/framework@v13.38.0 > symfony/routing@v8.1.9`

**Usage analysis:** imported by application code; affected API usage unconfirmed. Import check: symfony/routing is required by laravel/framework v13.38.0 (composer.lock) and `CompiledUrlMatcher` is used by Illuminate Routing (vendor/laravel/framework/src/Illuminate/Routing/CompiledRouteCollection.php, AbstractRouteCollection.php) on every request. Affected-precondition check: the bug fires only for routes that define a host (with placeholders) — `routes/web.php` (the sole route file, registered in bootstrap/app.php `withRouting(web: ...)`) declares every route without `domain()`/host constraints, and `config/` contains no Symfony security access_control definitions. The only route-file reference to hosts is none (`rg -n 'domain\(|host\(' routes/` → empty). There is no host-placeholder route and no path-based authorization rule, so no source reaches a desyncable sink. This is a prioritization signal from static analysis, not a proof of exploitability or of safety.

## Impact

In the abstract, an unauthenticated attacker could route a request to a controller while path-based access-control rules evaluate a different path, bypassing authorization. In this application there are no host-constrained routes and no Symfony path-based access rules — authorization is Laravel middleware and in-controller role checks — so the desync has no rule to bypass and the vulnerable path is not reachable.

## Contextual CVSS

symfony/routing v8.1.9 is imported transitively by laravel/framework v13.38.0 and its `CompiledUrlMatcher` executes on every request (vendor/laravel/framework/src/Illuminate/Routing/CompiledRouteCollection.php). The vulnerability requires (a) routes constrained to a host that contains a placeholder, and (b) path-based authorization rules (Symfony access_control / firewall patterns) that can be desynced from the matched route. Neither exists here: `routes/web.php` defines no `domain()`/host constraints (`rg -n 'domain\(|host\(' routes/` → none) and authorization is Laravel middleware/role checks, not Symfony path rules. With no host placeholders there is no host/path interpretation gap to exploit, so contextual impact is N/N/N; AC:H reflects the absent precondition.

## Remediation

Run `composer update symfony/routing` (or bump laravel/framework to a release resolving routing >= 8.1.11). No application change required; no host-constrained routes or path-based security rules exist.
